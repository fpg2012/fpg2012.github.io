git使用速查表

1. 配置与仓库

命令/快捷键 说明
git init 初始化当前目录为仓库
git clone <url> 克隆远程仓库
git config --global user.name "name" 设置全局用户名
git config --global user.email "mail" 设置全局邮箱
git config --global init.defaultBranch main 设置默认分支名
git config --list 查看所有配置
git status 查看工作区状态
git remote -v 查看远程仓库
git remote add origin <url> 添加远程仓库

2. 暂存与提交

命令/快捷键 说明
git add <file> 暂存指定文件
git add . 暂存所有改动
git add -p 交互式暂存部分改动
git commit -m "msg" 提交并写提交信息
git commit --amend 修改上一次提交
git commit --amend --no-edit 追加改动但不改信息
git restore <file> 撤销工作区修改
git restore --staged <file> 取消暂存
git rm <file> / git mv <a> <b> 删除 / 重命名文件
git clean -fd 删除未跟踪的文件和目录

3. 查看历史与差异

命令/快捷键 说明
git log --oneline --graph --all 紧凑的图形化历史
git log -p <file> 查看某文件的提交与改动
git show <commit> 查看某次提交的详情
git diff 工作区与暂存区的差异
git diff --staged 暂存区与上次提交的差异
git diff <branch1>..<branch2> 两个分支的差异
git blame <file> 逐行查看最后修改者
git reflog 查看 HEAD 移动记录（救急用）

4. 分支

命令/快捷键 说明
git branch / git branch -a 查看本地 / 所有分支
git switch <branch> 切换分支（推荐）
git switch -c <branch> 新建并切换分支
git checkout -b <branch> 新建并切换分支（旧写法）
git branch -d <branch> 删除已合并分支
git branch -D <branch> 强制删除分支
git branch -m <old> <new> 重命名分支
git merge <branch> 合并分支到当前分支
git rebase <branch> 将当前分支变基到另一分支
git cherry-pick <commit> 拣选某个提交

5. 远程与同步

命令/快捷键 说明
git fetch 拉取远程更新但不合并
git pull --rebase 拉取并以变基方式合并
git push / git push -u origin <branch> 推送 / 首次推送并关联
git push --force-with-lease 安全强推（覆盖前检查远端）
git tag <name> / git push --tags 打标签 / 推送标签
git remote remove <name> 删除远程仓库

6. 撤销与回退

命令/快捷键 说明
git revert <commit> 生成一个反向提交（安全）
git reset --soft HEAD~1 撤销提交，保留暂存
git reset --mixed HEAD~1 撤销提交与暂存，保留改动
git reset --hard HEAD~1 彻底回退（丢弃改动，慎用）
git stash / git stash pop 暂存 / 恢复当前改动
git stash list 查看 stash 列表
git checkout <commit> -- <file> 取回某文件的旧版本

7. 工作区（worktree）

命令/快捷键 说明
git worktree add <path> <branch> 在指定路径检出已有分支
git worktree add -b <new> <path> 新建分支并在新工作区检出
git worktree list 列出所有工作区
git worktree remove <path> 删除工作区
git worktree move <old> <new> 移动工作区
git worktree prune 清理已失效的工作区记录
git worktree lock <path> 锁定工作区（防止被 prune）
git worktree unlock <path> 解锁工作区

8. 大文件（LFS）

命令/快捷键 说明
git lfs install 在当前用户启用 LFS
git lfs track "*.psd" 让 LFS 跟踪匹配文件（写入 .gitattributes）
git lfs untrack "*.psd" 取消跟踪
git lfs ls-files 列出被 LFS 管理的文件
git lfs status 查看 LFS 状态
git lfs fetch / git lfs pull 拉取 LFS 对象
git lfs push --all origin 推送所有 LFS 对象到远端
git lfs migrate import --include="*.zip" 把历史中的大文件迁移到 LFS
git lfs env 查看 LFS 配置环境
git lfs logs last 查看最近一次 LFS 操作日志

9. 子模块（submodule）

命令/快捷键 说明
git submodule add <url> [path] 添加子模块
git submodule status 查看子模块状态
git submodule init 初始化 .gitmodules 中的子模块
git submodule update 检出子模块所记录的提交
git submodule update --init --recursive 递归初始化并检出（克隆后常用）
git clone --recurse-submodules <url> 克隆时一并拉取子模块
git submodule update --remote 更新到子模块远端的最新提交
git submodule foreach '<cmd>' 对每个子模块执行命令
git submodule sync 同步 URL 到 .git/config
git submodule deinit <path> 注销子模块
git config -f .gitmodules submodule.<name>.url <url> 修改子模块 URL
git rm <path> 删除子模块（还需清理 .git/config）

10. 补丁（format-patch / am）

命令/快捷键 说明
git format-patch -1 <commit> 为单个提交生成补丁
git format-patch <range> 为一段范围生成补丁（如 main..feature）
git format-patch -o <dir> <range> 指定补丁输出目录
git format-patch --stdout <range> 输出到标准输出
git format-patch -n <range> 生成带序号的文件名
git am <file.patch> 应用补丁并保留作者与提交信息
git am *.patch 依次应用多个补丁
git am --3way <file.patch> 以三方合并方式应用
git am --continue / --skip / --abort 冲突后继续 / 跳过 / 放弃
git apply <file.patch> 只把改动应用到工作区，不提交
git apply --check <file.patch> 仅检查补丁能否应用

11. 配置文件（~/.gitconfig）示例

[user]
    name = nth233
    email = fpg2012@foxmail.com

[init]
    defaultBranch = main

[core]
    editor = vim

[alias]
    st = status
    co = checkout
    br = branch
    ci = commit
    lg = log --oneline --graph --all
    unstage = reset HEAD --

[color]
    ui = auto
  • 命令中的 <...> 为占位符，使用时替换为实际内容。
  • 用 git help <command> 或 git <command> -h 查看帮助。
  • 同一分支不能同时检出到多个工作区。
  • 父仓库记录的是子模块的某个提交而非分支；改完子模块要回到父仓库提交指针，别人 pull 后再 submodule update 才能对齐。
  • LFS 需要远端支持，克隆前先 git lfs install；git lfs migrate 会重写历史，执行前备份。
  • git am 使用前建议先 git am --abort 保证工作区干净。
  • reset --hard、push --force、clean -fd 会丢失数据，执行前先确认。
