git常用工作流

1. 修改上一次提交

追加改动到上一次提交，但不修改提交信息：

git add .
git commit --amend --no-edit

2. 把功能分支更新到最新 main

git switch main
git pull
git switch -
git rebase main

3. 回退误提交但保留改动

撤销提交，改动退回暂存区：

git reset --soft HEAD~1

4. 撤销已推送的提交

用一个反向提交来抵消，不会改写历史：

git revert <commit>
git push

5. 找回丢失的提交

先看 HEAD 的移动记录，再基于目标提交建分支：

git reflog
git switch -c rescue <commit>

6. 只提交部分改动

交互式挑选要暂存的代码块：

git add -p
git commit -m "msg"

7. 临时切换任务

把当前未完成的改动收起来，办完事再恢复：

git stash -u
# ... 处理其它事情 ...
git stash pop

8. 同时开发两条分支

用 worktree 在另一个目录检出分支，无需来回切换：

git worktree add ../proj-hotfix hotfix
# ... 在 ../proj-hotfix 里工作 ...
git worktree remove ../proj-hotfix

9. 通过邮件收发补丁

把一段提交导出为补丁：

git format-patch -o /tmp/patches main..feature

收到补丁的一方直接应用（保留作者与提交信息）：

git am /tmp/patches/*.patch

10. 克隆或更新子模块

克隆时一并拉取：

git clone --recurse-submodules <url>

已有仓库则递归初始化并检出所记录的提交：

git submodule update --init --recursive
  • 命令中的 <...> 为占位符，使用时替换为实际内容。
  • revert 比 reset 安全，适合撤销已经推送的提交。
  • git am 前建议先 git am --abort 清空未完成状态，保持工作区干净。
  • git rebase、git format-patch 前先确认工作区干净，避免冲突丢失改动。
